# Contributing to AndyChoir

> **Язык:** Русский · [English](CONTRIBUTING.md)

Спасибо за интерес к проекту! Ниже — как собрать, протестировать и вносить изменения.

## Требования

- **Rust** (stable) с целью `wasm32-wasip2`:
  ```sh
  rustup target add wasm32-wasip2
  ```
- **Nix** (опционально): `nix develop` предоставляет всё нужное окружение
  (см. `flake.nix`). Запуск хоста, которому нужны MCP-серверы (`mcp-nixos`
  и т.п.), производится через `nix develop`.

## Сборка

```sh
make host      # хост (src/)
make plugins   # все wasm-плагины (plugins/*/)
make all       # host + plugins
```

> Примечание: wasm-файлы собираются в `plugins/*/target/`, а не в корневой `target/`. Полная очистка — `make clean` (чистит корневой target и target плагинов). Если вы добавляете свой плагин, не забудьте добавить его в Makefile во все нужные цели.

## Тесты

```sh
cargo test -p andychoir --lib   # тесты хоста
cd plugins/<имя> && cargo test  # unit-тесты плагина (если есть)
```

Перед вливанием PR убедитесь, что сборка проходит **без предупреждений** и все
тесты зелёные.

## Структура проекта

- `src/` — хост: шина сообщений, движок wasm, транспорт (http/ws/net/mcp), консоль.
- `wit/plugin.wit` — WIT-интерфейсы между хостом и плагинами.
- `plugins/` — wasm-плагины:
  - `front_*` — фронтенды (console, http, ws);
  - `agent_plugin` — LLM-агент;
  - `tool_*` — инструменты;
  - `mcp_client_plugin` — клиент MCP-серверов.

## Как вносить изменения

1. Форкните репозиторий и создайте ветку.
2. Вносите изменения **аддитивно**: не ломайте существующие пути без нужды.
3. Добавляйте тесты на новую логику.
4. Прогоните сборку и тесты.
5. Откройте Pull Request.

## Стиль

- `cargo fmt` и `cargo clippy` перед отправкой.
- Без предупреждений компилятора.
- Комментарии — на русском или английском (единообразно в рамках файла).
